# 泊车任务集与评测 V2

适用 Ranger Mini V3：长 0.72 m、宽 0.50 m；输入为定位、HDMap、感知结果。暂不接入点云、图像。使用受车身几何和曲率约束的搜索规划器，V5 网络权重未重新训练。

## 场景集合

`../scene_editor/examples/parking_missions_v2/all.suite.json` 包含 138 个独立场景。

| 分组 | 数量 | 覆盖 |
|---|---:|---|
| 基础泊入 | 36 | 平行、垂直、45°斜列 × 0.55/0.60/0.90 m 车位 × 1.20/2.40 m 通道 × 车头/车尾入位 |
| 基础泊出 | 36 | 从对应停车姿态出发，完整车身离开车位，到通道出口停稳 |
| 连续泊入泊出 | 36 | 泊入停稳、等待 2 s、重新规划泊出；评测至少 1 s 连续入位停稳 |
| 起始姿态扰动 | 12 | 窄通道、0.55/0.90 m 车位，横向 ±8 cm、朝向 ±5° |
| 静态障碍 | 6 | 上述车尾入位组合，通道端部障碍 |
| 车位占用 | 6 | 目标被静态物体占用，预期原地安全拒绝，不算泊车成功 |
| 通道来车 | 6 | 初始静止等待来车驶离，再执行泊入 |

0.55 m 对应总宽多 5 cm；0.60 m 对应两侧各多 5 cm。车位及地图由 `parking_project.py` 生成，任务由 `parking_suite.py` 生成。每个正向任务保存完整自行车模型轨迹见证，独立检查完整车身、区域边界、曲率及静态障碍；场景和评测侧车文件通过 SHA256 绑定。车位占用预期须确认永久障碍与目标车身重叠，不能把任意停车改判通过。

各分组可分别运行 `in.suite.json`、`out.suite.json`、`in_out.suite.json`、`robustness.suite.json`。地图是 36 个隔离实验单元，不是连通停车场交通测试。

## 指标与判定

| 指标 | 定义及门槛 |
|---|---|
| 泊入成功率 | 泊入/连续任务成功数除以全部对应正向任务数；全车入位、朝向误差 ≤2°、停速 <0.02 m/s，且符合车头/车尾入位要求 |
| 泊正率 | 上述任务中，朝向误差 ≤1°、车身中心横向误差 ≤1 cm、纵向误差 ≤3 cm；连续任务须连续泊正至少 1 s；同时给出成功泊入条件下的泊正率 |
| 泊出成功率 | 泊出/连续任务中，最终后轴目标距离 ≤3 cm、朝向误差 ≤2°、停车且完整车身离车位 ≥10 cm |
| 任务成功率 | 完成预期全部阶段，并通过碰撞、边界、运动学、轨迹连续性等现有门禁；单独泊入还要求后轴目标距离 ≤3 cm |
| 安全拒绝率 | 被占用车位任务中，最后至少 5 s 保持在初始位置 3 cm 内、速度 <0.02 m/s，并通过安全门禁；与正向任务分母隔离 |
| 规划耗时 | 每次路径搜索及其 P50/P95/P99/max；后续无搜索周期独立统计，保留总规划耗时和 >100 ms 帧数 |
| 效率 | 仿真任务时间、首次启动时间、首次入位时间、停稳驻留时间、换挡次数、行驶距离、相对可行见证的路径长度比 |
| 精度 | 横向/纵向/朝向误差、边界余量、左右间隙不均衡近似值、最终目标距离、泊出车身间距 |
| 安全 | 原生真值 OBB 碰撞数、全车越界帧、最小障碍间距、最小边界距离、曲率违规、规划发布连续性 |
| 平顺性 | 纵向/横向加速度、jerk、yaw rate 的 P95/max，停车次数及倒车距离 |

门槛是当前实验车的工程验收约定，未经实车标定，不是行业认证。规划耗时是真实墙钟时间；任务时间和启动等待是仿真时间，不能相加冒充真实完成耗时。效率和平顺性目前作为诊断指标，不设未经验证的舒适性门槛。见证不是最短路径，路径长度比可能小于 1。连续任务的精度取最长合格停车区间的中点，避免把随后泊出的轻微运动当成停车误差。

任务集分母保留失败、取消及缺少分析的任务；多次重复必须全部通过。运行中的评分标记 `IN_PROGRESS`。无碰撞分析等数据保留未评估数量，不能称为零碰撞通过。分组统计包括任务类型、车位类型、宽度、通道宽度和入库方向。

## 接入与复测

单任务：Web Monitor 的 Sim → 任务详情 → Full result analysis，查看 `quality_metrics.runs[].parking`、`collision`、`planning_continuity`。任务集运行结束保存 `parking-scorecard.json`。

容器内执行：

```bash
cd /apollo_workspace/modules/simulation/simulator
python3 run_quality_regression.py \
  --state-dir /apollo_workspace/data/simulation/parking-missions-20261001/full \
  --suite /apollo_workspace/modules/simulation/scene_editor/examples/parking_missions_v2/all.suite.json \
  --workers 4
```

复测应使用新的 `--state-dir` 保存独立结果。Web Monitor `/api/sim` 的 `parking_scorecard` 请求传入 `suite_id` 可查询聚合评分；后端以相同代码计算，现有页面仍在详情中展示单任务分析。

## 本轮改进与范围

- 增加明确的泊出/连续任务命令和阶段状态，完成泊入时不提前结束连续任务。
- 泊出从真实停车姿态构建路由，目标使用通道出口，修正平行车位的反向同车道路由失败。
- 搜索使用结构化哈希键、固定车身顶点缓存；先保留容易求解的精确目标反向搜索，再有限尝试正向搜索，最后保留完整搜索预算。
- 初始车辆静止且通道有移动车辆时保持停车；车位被占用时保持停车并限频重试。

V2 初版移动车辆测试仅验证初始等待后泊入。后续已补齐泊车途中动态制动、等待与路径恢复，并通过独立的 48 个 trigger 场景；见 [PARKING_DYNAMIC_FIX.md](PARKING_DYNAMIC_FIX.md)。理想跟随器会精确执行轨迹，厘米级指标不是 Control 或实车精度。窄车位只有约 2.5 cm 单侧余量，后续必须加入定位噪声、控制偏差和车辆尺寸不确定性再评估可用性。

实测结果及优化前后比较见 `PARKING_MISSIONS_V2_RESULTS.md`；原始失败和修复后的运行分别保留，不覆盖历史结论。

新增泊车途中行人、双向来车与连续干扰的独立集合见 [PARKING_DYNAMIC_TRIGGERS.md](PARKING_DYNAMIC_TRIGGERS.md)。
