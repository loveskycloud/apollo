## 实际改进

1. 新增泊出和泊入后泊出任务。连续任务先完成停车驻留，再切换到出口目标；不能只到出口就通过。
2. 修复平行泊出在 Routing 阶段的反向同车道请求：采用真实起始姿态及前方出口目标。
3. 减少路径搜索中的车身顶点分配和字符串哈希开销；保留容易求解的目标侧搜索，再有限尝试另一方向，最后使用完整预算。
4. 增加初始来车等待及占用车位的限频重试；未知动态变化仍明确失败，不吞掉失败或跳过安全检查。
5. 评测分开搜索与稳定周期，增加持续泊正、泊出车身脱离、全量任务分母和分组评分。

首次搜索仍有数十秒延迟，暂不满足实时泊车要求。最慢场景为 `diagonal45_w90_aisle120_rear__in__moving_aisle`；最多换挡为 `parallel_w60_aisle120_rear__in_out__base`，8 次。后续优化应先针对搜索预算、启发式和换挡代价做同集复测，保留窄位安全约束，不以扩大车位或缩小车身提高通过率。

## 复现与产物

根目录：`data/simulation/parking-missions-20261001/`。

- `full/`：138 个原生任务的完整录包、配置快照、碰撞结果、原始分析。
- `full-reviewed/summary.json`、`full-reviewed/parking-scorecard.json`：最终持续泊正口径重算结果；录包来源仍为 `full/`。
- `review_parking_metrics.py`：复核脚本；不会覆盖原始任务分析。
- `driving-regression/summary.json`：24 个普通行驶回归任务。
- `web-repeat-validation.json`：6 个 Web Monitor 任务、各重复两次的完整分析。
- `benchmark/`：配对测试的两个二进制、候选搜索头文件、哈希清单及复现脚本。
- `build.log`、`planner-tests.log`：编译安装和 C++ 测试证据。

`buildtool build -p modules/simulation` 成功；29 项 C++ 规划测试、46 项 Python 指标/任务/场景测试通过。单独直接调用 Bazel 测试曾因容器缺少第三方库链接路径失败；采用同一源码及仓库 GTest 直接编译的 29 项测试全部通过，完整 buildtool 编译和原生仿真也通过。

Web Monitor 后端已更新，原有 773 个任务保留，并新增 6 个重复验收任务。在 Sim 中选择 `泊车任务 V2 · all` 可再次运行；各任务的 Full result analysis 查看指标，`parking_scorecard` 后端接口提供任务集统计。没有新增单独的前端评分面板。

当前只能说明这些确定性仿真工况通过。理想跟随导致停车中心和朝向误差接近数值精度，不等于实车厘米级精度；尚未验证控制滞后、定位误差、尺寸误差或泊车途中突发障碍。V5 权重未重新训练，本轮收益属于泊车规划、任务状态和评测能力。
